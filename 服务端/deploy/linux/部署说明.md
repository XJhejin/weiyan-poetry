# CentOS / Linux 无界面服务端

本目录提供 systemd 部署模板。需要先确认目标服务器的系统版本、Python、systemd、现有服务和数据；准备好这些文件不代表已完成远程部署。不要将 Mac DMG 或 Windows exe 安装到 CentOS。

## 运行环境

使用 Python 3.12 和 `requirements-headless.txt`，不需要桌面、显示器或 pywebview。先检查 `/etc/os-release`、`python3.12 --version` 和 `systemd --version`，再根据实际版本安装系统依赖。不要替换系统自带 Python，也不要关闭 SELinux 或整个防火墙。旧系统若不能提供兼容运行环境，需要先另行选择升级系统或容器方案。

在开发电脑运行 `python 服务端/tools/build_linux_bundle.py`，在根目录 `build-output/linux/` 生成 `.tar.gz` 和 SHA-256 校验文件。压缩包只包含明确列出的服务端代码、运行依赖清单和部署模板，不包含本机数据库、账号资料、聊天记录、密钥或安装包。它是源码部署包，不是经过发布签名验证的客户端自动更新包。

## 目录与安装

在服务器上确认 `/opt/weiyan`、`/etc/weiyan`、`/var/lib/weiyan` 没有现存安装。已有安装应先备份并制定升级步骤，不能覆盖其数据或创建第二个服务共用同一个数据库。

新安装采用：

- `/opt/weiyan/server/`：压缩包中的 `server.py`、其余 `.py` 文件和 `requirements-headless.txt`。
- `/opt/weiyan/venv/`：专用 Python 虚拟环境，使用 `python3.12 -m venv /opt/weiyan/venv` 创建，然后用该环境的 `python -m pip install -r /opt/weiyan/server/requirements-headless.txt` 安装依赖。
- `/etc/weiyan/server.env`：从 `server.env.example` 复制，供管理员调整监听地址和端口。
- `/var/lib/weiyan/`：账号、公钥、群关系和未投递密文，安装时创建并授予 `weiyan` 账号访问权限，独立于源码目录。
- `/etc/systemd/system/weiyan-server.service`：复制本目录的同名文件。

创建不允许交互登录的系统账号 `weiyan` 和同名组，让源码、虚拟环境和配置归 root 管理。模板固定以 `weiyan` 运行，使用 `install -d -o weiyan -g weiyan -m 0700 /var/lib/weiyan` 创建数据目录，不开放管理 UI。模板避开 systemd 219 不支持的 `StateDirectory` 和 `ProtectSystem=strict`；安装前仍应使用 `systemd-analyze verify /etc/systemd/system/weiyan-server.service` 检查目标系统是否支持所有指令。

检查通过后运行：

```sh
sudo systemctl daemon-reload
sudo systemctl enable --now weiyan-server
sudo systemctl status weiyan-server --no-pager
curl --fail --silent http://127.0.0.1:23074/api/health
```

健康检查应包含 `"ok": true` 和版本号。查看日志使用 `sudo journalctl -u weiyan-server -n 100 --no-pager`。模板配置了故障重启和开机自启。

## 对外连接

初始模板只监听 `127.0.0.1:23074`。先在回环地址完成注册、连接、加密消息投递与重启后数据保留验证，再配置公网连接。

推荐使用有效证书的 HTTPS 反向代理，代理到 `http://127.0.0.1:23074`，客户端在连接设置中填写实际的 `https://域名`。代理必须支持 `/api/socket` 的 WebSocket Upgrade、保留原始 Host、允许至少 48 MiB 的请求体并为长连接配置适当超时；不要缓存 API 请求、记录请求正文或 Cookie。服务端会校验 Origin 和 Host，代理不要把 Host 改成回环地址。

如部署方案需要直接监听网卡，在 `/etc/weiyan/server.env` 中设置 `WEIYAN_HOST=0.0.0.0` 或服务器的本机地址，再重启服务；云安全组与系统防火墙仅开放需要的端口。公网 NAT 地址不一定是可绑定的本机地址。直接 HTTP 连接不能保护登录密码与会话凭据，聊天消息端到端加密不代替 HTTPS。发布客户端默认地址仍为 `https://156.225.28.175:23074`，部署模板不会修改客户端已经保存的连接地址。

无界面模式不启动管理页面或管理端口。如以后需要远程管理，须通过 SSH 隧道等方式访问回环管理接口，不能直接将管理页面公开到互联网。

本项目提供 `Caddyfile.example` 和 `weiyan-proxy.service`。它们以 `https://156.225.28.175:23074` 对外提供服务，后端改为仅监听 `127.0.0.1:23174`；其他服务器需相应修改代理服务中的 `WEIYAN_PUBLIC_IP`。Caddy 显式使用 Let's Encrypt 的 `shortlived` 配置申请受信任的 IP 地址证书，并自动续期；公网 TCP 80 必须持续可达以便 HTTP-01 验证，不能只开放 23074。Caddy 的管理 API 已禁用。

该代理模板使用独立的无登录账号和组 `weiyan-proxy`，需要预先创建 `/var/lib/weiyan-proxy`（该账号拥有，权限 `0700`），Caddy 放置在 `/opt/weiyan/caddy/caddy`，配置位于 `/etc/weiyan/Caddyfile`。为兼容 systemd 219，给 root 所有、普通用户不可修改的 Caddy 二进制设置 `cap_net_bind_service=+ep`，仅授予绑定 80 端口的能力；模板限制能力边界并以普通账号运行。替换 Caddy 二进制后需重新检查文件能力。安装其他服务器前，应先验证其系统、Caddy 版本、证书申请和实际 TLS 信任情况，不能以自签名证书代替公网受信任证书。

## 备份和升级

备份时停止 `weiyan-server`，复制完整 `/var/lib/weiyan/` 到受控备份位置，再启动服务；不要只复制运行中的 SQLite 主文件而遗漏 WAL。升级前同时保留旧源码和依赖环境。新代码先在隔离目录和临时数据上验证，再停服务切换，保留配置和数据。若需要回滚数据库，应先停止服务，避免丢弃升级后新接收的未投递密文。

未投递密文永久保留，确认接收后删除，不设软件总容量限制。监控实际可用磁盘空间，不能通过定时删除待投递消息来腾出容量。不要将服务器数据、密钥、SSH 凭据或配置秘密提交到 GitHub。

Linux 源码部署由管理员更新代码和虚拟环境；桌面服务端的 DMG/ZIP 自动更新流程不用于此 systemd 服务。
