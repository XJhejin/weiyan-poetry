# CentOS / Linux 服务部署与远程控制

本目录提供 systemd、HTTPS 代理和受限 SSH 管理程序。发布使用的服务器为 `156.225.28.175`，CentOS 7.6、systemd 219；公网聊天入口 `https://156.225.28.175:23074`。其他机器应先检查系统、现有服务和数据，再调整配置，不能覆盖已有安装。

## 运行环境和目录

使用独立 Python 3.12，不替换系统 Python。`requirements-headless.txt` 提供运行依赖，无需桌面或 pywebview；服务进程用 `--browser --no-open` 在回环启动管理 HTTP，无需浏览器进程。

- `/opt/weiyan/python/`：独立 Python 运行库。
- `/opt/weiyan/versions/<版本或部署编号>/server/`：源码、管理 UI 和依赖清单，root 所有，目录 0755、文件 0644，普通服务账号不可修改。
- 同级 `venv/`：该版本的专用虚拟环境。旧安装可先指向原有 `/opt/weiyan/venv`；更新创建新的独立环境。
- `/opt/weiyan/current`：当前版本目录的符号链接，切换时原子替换。
- `/etc/weiyan/server.env`：`WEIYAN_HOST=127.0.0.1`、`WEIYAN_PORT=23174`，与本项目代理和控制端约定一致。
- `/var/lib/weiyan/`：账号、设备公钥、群关系及未投递密文；无登录账号 `weiyan` 所有，目录 0700、数据库 0600，独立于程序。
- `/opt/weiyan/control/`：root 所有的 `control_gateway.py`、`update.py`、`release_config.py` 及独立 `venv/`。安装固定版本 PyNaCl、certifi，不能放在普通服务账号可写的目录。
- `/var/lib/weiyan-control/`：root 所有、0700，保存更新任务、进度和更新前数据库备份。

新安装先创建无登录系统账号和组 `weiyan`、`weiyan-proxy`。将服务文件复制到 `/etc/systemd/system/`，用 `systemd-analyze verify` 验证，再执行 `systemctl daemon-reload`、`systemctl enable --now weiyan-server weiyan-proxy`。

模板兼容 systemd 219，不使用其不支持的 `StateDirectory`、`ProtectSystem=strict` 和 `AmbientCapabilities`。不要关闭 SELinux 或整机防火墙。已配置故障重启和开机自启；自启配置不代表已经重启整台服务器验证。

## HTTPS 和端口

`Caddyfile.example` 和 `weiyan-proxy.service` 使用 root 所有、普通账号不可修改的 `/opt/weiyan/caddy/caddy`。Caddy 以 `weiyan-proxy` 运行，数据目录 `/var/lib/weiyan-proxy` 归该账号所有、0700。为兼容 systemd 219，二进制设置 `cap_net_bind_service=+ep`，单元只允许该能力，替换二进制后需重新检查。

公网 TCP 23074 提供 HTTPS/WSS，代理到 `127.0.0.1:23174`；保留原始 Host，支持 WebSocket Upgrade，允许至少 48 MiB 请求体，不缓存 API，不记录 Cookie 或正文。管理口 `127.0.0.1:23175` 不得代理或公开。

Caddy 管理 API 禁用。使用 Let's Encrypt `shortlived` 配置申请受信任的 IP 证书并自动续期，公网 TCP 80 必须保持可达，以便 HTTP-01 验证；Caddy 可按验证需要临时监听 80。其他机器需调整 IP 和代理配置，不能用自签名证书代替受信任证书。

```sh
systemctl is-active weiyan-server weiyan-proxy
systemctl is-enabled weiyan-server weiyan-proxy
curl --fail http://127.0.0.1:23174/api/health
curl --fail https://156.225.28.175:23074/api/health
ss -lntp
```

## 远程控制授权

服务将每次启动的随机管理入口原子写到 `/var/lib/weiyan/admin-url`，0600，不把 token 输出到 systemd 日志。接口要求精确回环 Host、随机凭据和来源校验；账号列表不返回密码散列。

Windows 控制端位于 `服务器控制端/`，使用系统 OpenSSH，通过固定 JSON 操作调用管理程序。每个管理员设备使用独立公钥，在 `authorized_keys` 配置强制命令，示例格式：

```text
command="/opt/weiyan/control/venv/bin/python /opt/weiyan/control/control_gateway.py",no-agent-forwarding,no-port-forwarding,no-X11-forwarding,no-pty ssh-ed25519 <设备公钥> weiyan-control-<设备编号>
```

程序忽略 `SSH_ORIGINAL_COMMAND`，只允许状态、账号、启停、重启、更新和服务日志操作，不接受 shell、SQL、自定义文件路径或端口转发。受限密钥不能替代普通 SSH 运维登录。

Windows 私钥由原电脑与原账号 DPAPI 加密保存，配置登记通过原可信 SSH 会话取得的服务器主机公钥；严格校验主机密钥，不能自动接受身份变化。私钥、授权配置、数据库和 token 不得进入 GitHub 或公开安装包。

## 签名更新与回滚

`python 服务端/tools/build_linux_bundle.py` 生成明确文件名单的源码 tar.gz；单独的 `.sha256` 不提供发布者身份保证。正式发布通过 `客户端/tools/publish.py` 将 `server_linux_source` 加入 Ed25519 签名清单；只接受签名验证及哈希、大小校验均通过的正式发布包。

更新由 systemd 独立运行，关闭控制端不影响任务。先安全解包到新目录、创建并测试独立依赖，再短暂停止 HTTPS 代理和聊天服务，用 SQLite backup 备份数据库，原子切换 `current` 并启动新版本。健康检查通过后恢复公网入口；失败恢复旧程序和更新前数据库，检查旧版本再恢复入口，避免客户端消息在验证阶段进入新库。更新期间其他控制端不能修改账号或启停服务。

旧版本和数据库备份保留在 root 受限目录。不要只复制运行中的 SQLite 主文件而遗漏 WAL；手动回滚前先停公网入口和服务，避免丢弃新接收的消息。

未投递密文永久保留，不设软件总容量配额，接收确认后删除。磁盘可在控制端查看，不得用定时删除未投递消息来腾出空间。

查看日志：`journalctl -u weiyan-server -n 100 --no-pager`。Linux 使用源码更新流程，不能安装 Windows ZIP/MSI 或 Mac DMG。
