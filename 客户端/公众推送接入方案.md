# HushLeaf 公众推送接入方案与开通清单

准备日期：2026-10-20。**当前仅准备方案：账号及通道尚未开通，2.2.1 未集成厂商推送 SDK。** 2.2.1 已移除常驻服务通知；应用进程被结束后不能保证及时提醒，重新打开后补收。

建议选择一个统一平台（极光或个推二选一）管理厂商通道，国际设备使用 FCM。通常仍需账号持有人完成各厂商实名、应用登记及推送申请；覆盖范围、审核、资费和配额以开通时官方控制台为准。

## 一次性准备

- 正式应用：HushLeaf · 未言诗集，固定包名 `com.weiyan.poetry`。沿用原正式签名，**不可重新生成证书**。
- 准备开发者身份、主体资质及可验证联系人。公众分发需要的备案和商店材料由账号持有人在官方平台核对办理。
- 准备官网 `https://www.hushleaf.top/`、公开隐私说明、功能截图、测试 APK 和“即时通信新消息提醒”用途说明。接入前补齐第三方 SDK、数据类型、用途和隐私政策。
- 从正式签名 APK 使用 `apksigner verify --print-certs` 导出公开 SHA-256 / SHA-1 指纹，登记到厂商应用。JKS、密码和服务端秘密不得上传公开仓库或发到聊天中。

## 接入设计与边界

1. 用户同意更新后的隐私说明后才初始化 SDK；按系统要求申请通知权限。关闭通知、停止接收、注销和撤销设备必须生效，不循环弹窗诱导。
2. 将通道 token 绑定到已验证的加密设备；token 变更及时更新，退出及撤销时解绑；不写入普通日志、公开管理界面或发布包。
3. 密文持久化成功后异步推送，推送失败不阻塞消息应答、不丢消息，保留永久离线密文且无软件总容量限制。
4. 推送载荷仅含必要的随机投递标识，系统展示固定“收到新的加密消息，打开查看”；不得发送聊天正文、昵称、引用、文件名、附件 URL 或解密密钥。点击后通过既有 HTTPS 拉取密文，在设备解密。
5. **免打扰与 @ 是接入前必须解决的设计门槛**：当前这些信息在本机或端到端加密内容内，服务器不能从密文判断。需明确经用户知情的最少通知路由元数据及签名校验方案，或在支持的设备解密唤醒后决策；不得将所有密文都变为系统弹窗，也不得声称纯数据推送在所有后台限制下都能唤醒。
6. 与现有连接使用稳定去重标识，连续消息合并提醒；历史同步、自发消息和已查看会话不重复提醒，点击定位正确会话。缺少配置时显示实际状态，不显示“系统推送已启用”。
7. 不保证断网、用户强行停止或禁用通知后仍可即时提醒；不能用普通后台线程代替系统推送。

## 真机验收

- 每个开通通道至少一台真实设备，记录型号、ROM、版本、通道和到达耗时，不能只用模拟器宣布全部覆盖。
- 分别测试前台、返回桌面、划走任务、息屏、长时间闲置、省电、断网重连、重启后重新允许运行，以及系统强行停止后的实际限制。
- 测试普通免打扰、明确 @、全局禁用、停止接收、系统禁止通知、注销、撤销设备与多设备；通知历史和锁屏均无正文。
- 覆盖安装保持原签名与账号，旧常驻通知不复现；推送与在线连接不重复响铃，历史补齐静默，断线后正确补收。
